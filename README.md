# Oscillo

**示波器音乐可视化工具** —— 把音频信号渲染成矢量图形或像素点阵，支持 Y-T 时域与 X-Y 李萨如图形两种模式。

> 灵感来自 Jerobeam Fenderson 的 **Oscilloscope Music** 系列，比如《Primer》——用左右声道直接控制 CRT 电子束的 X / Y 坐标来绘制几何图形。

## 特性

| 功能 | 说明 |
|------|------|
| **Y-T 时域** | 经典示波器模式，边缘触发同步，显示 5ms ~ 50ms 的波形窗口 |
| **X-Y 矢量** | 左声道→X 轴，右声道→Y 轴，绘制李萨如图形 |
| **X-Y 像素** | 数字示波器风格，采样点对齐到像素网格，形成马赛克质感 |
| **像素连线** | 按距离绘制渐变透明度的连线，把点阵串成轨迹 |
| **孤立点淡出** | 与周围点距离过远的孤立采样点自动变淡，突出主图形 |
| **三种预渲染** | 实时 / LUT / 完整，可对比不同缓存策略的性能差异 |
| **WebGPU 加速** | 用 WGSL 着色器渲染波形，CPU 占用降低 5~8 倍 |
| **CRT 复古效果** | 扫描线 / 暗角 / 荧光泛光，模拟老式示波器质感 |
| **性能监控** | 实时显示每帧绘制耗时、1% Low、FPS，方便对比渲染路径 |

## 快速开始

项目使用 ES Module，**必须通过 HTTP 服务器访问**（`file://` 会被浏览器 CORS 策略拒绝）。

```bash
# 克隆或下载项目到本地
cd oscillo

# 方式一：Python 内置服务器
python3 -m http.server 8000

# 方式二：Node.js
npx serve .

# 方式三：VS Code 的 Live Server 插件，右键 index.html → Open with Live Server
```

浏览器打开 `http://localhost:8000`。

### 导入音频

- 点击「📁 导入音频」按钮选择文件
- 或把 MP3 / FLAC / WAV / OGG 拖拽到屏幕上

### 播放示波器音乐

1. 打开设置（齿轮图标或 `S` 键）
2. 启用 **X-Y** 模式
3. 播放 Primer 或其它示波器音乐
4. 调节「增益」到 1.5× ~ 2.0×，「线条」调到 1.0 ~ 1.5
5. 如果图形方向不对，试试设置里的 **L↔R**（交换声道）或 **Y 反相**

## 架构

### 数据流

```
音频文件
  ↓ decodeAudioData
AudioContext → AnalyserNode → Float32Array（时域采样）
  ↓
geometry.js  ──→ 生成渲染批次 batches[]
  ↓
renderer.render(batches)  ──→ 屏幕
```

### 核心抽象：渲染批次

**几何生成**与**渲染后端**通过一个简单的数据契约解耦：

```js
{
  type: 'lines' | 'dots',
  data: Float32Array,
  // lines: 每段 4 个 float [x0,y0,x1,y1]
  // dots:  每个 2 个 float [x,y]，尺寸由 size 指定
  width?: number,       // lines 专用
  size?: number,        // dots 专用
  color: [r,g,b,a],
}
```

`geometry.js` 只关心如何从音频采样生成这些批次；渲染器只关心如何把批次画到屏幕上。**换后端（比如 WebGL、SVG）只需要实现一个新的 Renderer 类**，主循环完全不动。

### 模块职责

| 模块 | 职责 |
|------|------|
| `state.js` | 唯一状态源。所有模块从 `state` 读参数 |
| `audio.js` | 加载、播放、分析器、采样率探测。通过回调通知状态变化 |
| `lut.js` | 三种预计算资源：`XyLut`（坐标查表）、`YtLut`（采样索引）、`DotAtlas`（像素方块图集） |
| `geometry.js` | 纯函数，输入音频缓冲，输出渲染批次。不依赖 DOM |
| `perf.js` | 采样性能数据，管理浮层面板 |
| `renderers/*` | 实现 `init()` / `resize()` / `render(batches)` / `destroy()` 四个方法 |
| `main.js` | 把所有东西串起来：主循环、UI 绑定、渲染器切换 |

## 操作说明

### 显示模式

| 模式 | 用途 |
|------|------|
| **Y-T** | 时域波形。适合观察普通音频的波形包络 |
| **X-Y** | 矢量模式。适合示波器音乐，绘制几何图形 |
| **X-Y + 像素** | 数字示波器风格。采样点对齐到网格，形成颗粒感 |

### 显示开关

| 开关 | 效果 |
|------|------|
| **发光** | 波形叠加宽透明辉光层，更接近 CRT 荧光效果 |
| **等比** | X/Y 使用相同像素基准，防止图形被屏幕比例拉伸 |
| **L↔R** | 交换左右声道。有些示波器音乐需要反过来才正确 |
| **Y 反相** | Y 轴上下翻转 |
| **像素** | 只在 X-Y 模式下有效，切换像素点阵画法 |
| **连线** | 像素点之间按距离绘制渐变透明度连线 |
| **淡出** | 孤立点自动变淡 |

## 参数详解

| 参数 | 范围 | 说明 |
|------|------|------|
| **时基 TIME/DIV** | 0.2ms ~ 50ms | 每格水平时间。只在 Y-T 模式生效 |
| **增益 VOLTS/DIV** | 0.2× ~ 5.0× | 垂直放大倍数 |
| **触发 TRIG** | -1.00 ~ 1.00 | 边缘触发阈值。只在 Y-T 模式生效 |
| **音量 VOLUME** | 0% ~ 100% | 播放音量，不影响波形幅度 |
| **线条 / 像素** | 0.5px ~ 4.0（线条）<br>0.5px ~ 5.0px（像素） | 根据模式自动切换含义 |
| **连线强度 LINK** | 极弱 ~ 极强 | 像素连线的不透明上限 |
| **淡出强度 FADE** | 弱 ~ 极强 | 孤立点淡出的最大强度 |
| **帧率 FPS** | 不限 ~ 120 | 限制每秒最多重绘次数，0 为不限 |

## 性能对比

在 4096 采样点、X-Y 像素模式、60fps 目标下的典型数据（参考值，实际取决于硬件）：

| 渲染路径 | 平均耗时 | 1% Low | CPU 占用 |
|---------|---------|--------|---------|
| Canvas 2D + 实时 | ~6.2 ms | ~11 ms | ~37% |
| Canvas 2D + LUT | ~5.0 ms | ~9 ms | ~30% |
| Canvas 2D + 完整预渲染 | ~4.5 ms | ~8 ms | ~27% |
| **WebGPU** | **~0.6 ms** | **~1.2 ms** | **~4%** |

### 如何自己测

1. 按 `H` 打开性能面板
2. 播放同一段音频，等采样数超过 300
3. 点「重置」
4. 切换到另一种渲染路径
5. 等采样数再次超过 300，读取数据
6. 点「复制」保存结果对比

**公平对比要点**：同一音频、同一时间窗、同一套参数、目标帧率设为「不限」、等几百帧再读。

## 设计笔记

### 为什么用 LUT？

每帧对 4096 个采样点做 `halfW + v * ampX` 的乘法，看似不贵，但 60fps × 60s × 4096 点 ≈ 1500 万次运算。用 2048 档的查找表代替乘法，误差 < 1 像素，CPU 占用降低 30~40%。

同理，Y-T 模式里每点做 `(i/(pts-1)) * (win-1)` 的浮点除法、取整、减法，也用 LUT 预计算 `i0 / i1 / f` 三元组。

### 为什么 WebGPU 用 instanced draw？

像素模式下，Canvas 2D 每帧要处理几千个 `fillRect` + `fillStyle` 切换。WebGPU 用一次 `draw(4, N)` 就能画出 N 个点（每个点 4 个顶点，instanced），CPU 侧只需上传一次数据缓冲。

### 为什么几何与渲染要解耦？

音频可视化领域算法迭代很快（新的图形触发方式、新的采样映射）。把「数据怎么算」和「数据怎么画」分开，可以：
- 独立测试几何算法（无 DOM）
- 用同一套数据在不同后端上跑对比
- 换后端（WebGL / SVG / 未来 API）不动几何代码

### 为什么用 ES Module？

- 无打包步骤，`<script type="module">` 直接运行
- 浏览器原生支持，`import` / `export` 明确依赖关系
- 各模块天然隔离，不会污染全局作用域

代价是需要 HTTP 服务器（`file://` 会被 CORS 拒绝）。如果必须支持 `file://`，可以用一个简单的打包脚本把所有模块内联到 index.html。
